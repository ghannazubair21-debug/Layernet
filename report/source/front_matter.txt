@@ABSTRACT
Financial fraud is rare compared with the very large number of legitimate digital payments, so analysts must decide which transactions to examine first and must be able to explain why. Existing approaches range from fixed rules to supervised models such as Random Forest and gradient-boosted trees, and to sequence models that use a customer's transaction history. Many public demonstrations, however, report a single accuracy figure on highly imbalanced data, evaluate with random rather than chronological splits, or show dashboard scores whose origin is not stated.

LayerNet 2.0 was developed with an iterative and incremental process as two connected parts. The first is an investigation web application built with Next.js, React and TypeScript. It scores a manually entered transaction with a transparent rules baseline that gives an uncalibrated 0–100 priority score, lists every contribution, stores records in the browser, and presents them on dashboard, history, analytics, health and settings pages. It also offers an optional Gemini-based assistant for general questions and a benchmark page that replays saved XGBoost and Random Forest models on uploaded ULB-format rows through an integrity-checked server-side Python process. The second part is an offline Python research track. It evaluates tree-based and anomaly-detection models on the public ULB credit-card dataset with a chronological split, and studies recipient transaction history on the synthetic PaySim dataset with a one-layer Transformer encoder and a pre-registered, leakage-aware ablation.

The application passed 37 component and route tests, 11 unit tests and an end-to-end browser test, and its layout was checked at five screen widths. On the held-out ULB test split, which contains 74 fraud cases, Random Forest reached an Average Precision of 0.807 and XGBoost 0.773. On one PaySim test split, the Transformer recorded an Average Precision of 0.146, against 0.080 for a temporal linear model and 0.039 for a current-transaction-only model. In the three-seed history ablation, the history-enabled model scored higher for every seed (mean gain 0.048), but the 95 % interval includes zero, so the result is reported as partial.

The live score remains rules-based; the Transformer and the trained models are not part of live scoring, and the prototype is single-user, stores data locally and runs on one computer. These limits, and the use of synthetic data for the history study, are stated wherever results are reported.
