@APPENDIX II|Data Dictionary
LayerNet stores two JSON values in the browser's localStorage. Table A.2 describes the fields of one saved transaction under the key `layernet-transactions`, which holds an array of such records. The settings value under `layernet-settings` has one field, `theme`, whose allowed values are `system`, `light` and `dark`; any other stored value falls back to `system`.

!TABLE Fields of a saved transaction record
!WIDTHS 1.6,1.2,0.9,2.8
| Field | Type | Required | Meaning |
| transactionId | string | Yes | Identifier entered by the analyst; records are upserted by this value |
| accountId | string | No | Groups records for the behavioural baseline |
| timestamp | ISO 8601 string | Yes | Time of the transaction, stored in UTC |
| amount | number | Yes | Amount greater than 0 |
| type | string | Yes | Purchase, Refund or Withdrawal |
| location | string | Yes (form) | Free-text location entered by the analyst |
| channel | string | Yes (form) | Web, Mobile or POS |
| deviceId | string | No | Optional device identifier |
| riskScore | number | Yes | Rules baseline v1 priority score, 0–100, uncalibrated |
| risk | Low, Medium, High | Yes | Band derived from the score |
| status | Cleared, Reviewed, Flagged | Yes | Workflow status mapped from the decision Clear, Review or Block |

@APPENDIX IV|User Manual
**Starting the application.** Install Node.js 24 and run `npm install`, then `npm run dev`, and open `http://localhost:3000`. To use the assistant, set the `GOOGLE_GENERATIVE_AI_API_KEY` environment variable before starting the server. To use the Benchmark page, create the Python environment in `ml/.venv` from `ml/requirements.txt`.

**Analysing a transaction.** Open Analysis, fill in Transaction ID, Amount, Transaction Type, Channel, Location and Timestamp, and press Analyze Transaction. Fix any field marked with an error. The result dossier shows the score, risk, decision, the contribution of each rule and the limitations of the method. The record is saved to History automatically.

**Reviewing records.** Dashboard summarises saved records. History lets you search by transaction ID or location, filter by risk or type, sort by amount or score, and open a details drawer. Analytics shows breakdowns of saved analyses; these are not fraud rates.

**Running a benchmark.** Open Benchmark and choose a CSV file in the ULB format (Time, Amount, V1–V28 and an optional Class column; at most 2 MB and 5,000 rows). The page shows the scores of the saved XGBoost and Random Forest models, their agreement and, when labels are present, metrics for the uploaded rows only.

**Settings and data.** Settings changes the theme and can clear all locally stored records after confirmation. Clearing the browser's site data also deletes the records, because they are stored only in that browser.
